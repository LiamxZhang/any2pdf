# Any2PDF 产品与技术设计

日期：2026-11-01

## 目标

提供 Windows、Linux、macOS 本地便携 PDF 转换工具。用户下载对应系统的压缩包，解压后启动，无需安装 Python 或 Node.js。文件不上传到服务器。每个输入文件最多 10 GiB（10,737,418,240 字节），界面明确显示此单位。

“任何能转为 PDF 的文件”落实为可扩展的转换器体系及明确的格式支持清单；不能保证任意私有、损坏、加密或缺乏解码器的文件都能转换。10 GiB 是输入大小限制，转换能否完成还受格式、引擎、内存和磁盘空间影响。

## 路线比较与推荐

1. 推荐：本地桌面界面与随包转换引擎。保留原始文件路径，避免浏览器上传与大文件复制；离线使用，发行包较大，三个系统分别构建。
2. 本地浏览器界面与后台服务。界面开发方便，但需要本地端口、浏览器和文件传输，10 GiB 文件管理更复杂。
3. 纯浏览器网页。发布方便，但通用格式支持、内存限制与离线转换引擎不适合本项目要求。

## 推荐架构

Python 与 PySide6 桌面界面；独立工作进程执行转换；SQLite 持久化任务与历史；PyInstaller 构建每个系统独立的便携目录。转换器按格式注册，启动时探测能力，缺失引擎时显示原因。

标准发行包随附必要转换引擎和字体许可信息，避免要求最终用户另行安装依赖。若某个平台尚未成功完成引擎打包与启动验证，该平台标记为未验证，不宣称已完成免安装支持。

## 界面与操作

- 上传：按钮选择或拖入多个本地文件，显示名称、类型、大小、可用转换器；“上传”仅添加本地路径。
- 转换：队列、输出目录选择、开始、取消、状态、耗时和打开结果。引擎无法提供真实百分比时显示阶段与运行中状态。
- 历史记录：保存成功、失败、取消的任务，支持筛选、打开输出、重试与清空记录。清空记录不删除输入文件或生成的 PDF。

提供中文和英文界面，默认中文；用户选择持久保存，语言切换同步更新状态与结构化失败原因。失败时明确显示原因，并提供原始诊断日志。默认输出到用户文档目录中的 Any2PDF 文件夹，允许修改；同名输出自动生成新名称，不覆盖已有文件。

## 首版格式与引擎

- PDF：校验后复制为新的输出 PDF，以分块方式复制。
- 常见图像：JPEG、PNG、BMP、TIFF、WebP，转为单页或多页 PDF；逐页处理多帧图片，保留纵横比，明确处理超大像素图像的内存风险。
- 纯文本及代码：TXT、CSV、JSON、Markdown、日志和常见源代码，分段读取并分页排版，使用支持中文的随包字体。首版 Markdown 按文本排版。
- Office/OpenDocument：DOC、DOCX、XLS、XLSX、PPT、PPTX、ODT、ODS、ODP、RTF，使用 LibreOffice 无界面转换，每个任务隔离用户配置目录。
- HTML/HTM：通过随包 Chromium 打印成 PDF；默认禁止网络访问，允许文档自身目录下的本地样式与图片，明确脚本与资源限制。
- 其他类型：给出不支持或缺失引擎的明确提示；不伪装成功，也不仅修改扩展名。

## 大文件、任务与异常

文件只保存路径和元数据，不整体读入内存；输入大小在入队和执行前双重检查；默认单任务串行执行，保护内存。转换输出先写入任务临时目录，成功校验 PDF 后发布到目标目录。

取消时终止工作进程及其子进程；失败与取消清理临时文件。保留错误摘要与日志以便诊断。应用退出时提示运行中的任务，重启后将中断任务标记为失败并允许重试。检查输出目录可写性及可用磁盘空间；不承诺任何固定输入与输出大小比例。

## 隐私与安全

不调用云端转换接口，不收集文件内容。使用参数列表启动引擎，不通过 shell 拼接文件名。引擎使用独立临时目录，不自动打开输出；不支持密码文件时明确报错。说明本地转换器并非安全沙箱，随发行版持续更新引擎。

## 构建与 GitHub 发布

GitHub 仓库建议名称 any2pdf，默认公开并采用 MIT 许可；第三方引擎与字体保留各自许可，具体再分发许可必须在打包时核查。

GitHub Actions 按 Windows、Linux、macOS 分别构建，输出各自可启动的压缩包、SHA256 和第三方许可文件。首版至少覆盖 Windows x64、Linux x64、macOS arm64，其他架构不宣称兼容。Linux 需要桌面图形环境，macOS 未签名发行版可能需用户在系统中允许首次打开；免安装不代表能跳过系统安全策略。

在有可用 GitHub 身份验证后创建仓库、推送源码并触发构建，只有构建成功并验证产物后才发布对应版本。GitHub 身份验证不能由本地 git 作者信息代替。

## 验收与验证

自动测试覆盖格式路由、大小边界、重名保护、历史持久化、失败清理、取消及进程清理、文本分页与中文、有效 PDF 校验。使用稀疏文件验证 10 GiB 大小边界而不实际分配同等内存；此测试不代表完成任意 10 GiB Office 文件转换。

真实转换测试至少覆盖中文文本、图片、多页 TIFF、PDF、Office 和本地 HTML。各平台 CI 执行构建和可行的无界面冒烟测试，记录尚需实际桌面验证的项目，不把单平台验证表述为跨平台实测完成。
